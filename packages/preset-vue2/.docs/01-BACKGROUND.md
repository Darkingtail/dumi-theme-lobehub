# 背景与动机

## 1. Vue 2 的现状

尽管 Vue 3 已经发布多年，Vue 2 仍然在企业级应用中占据重要地位：

- **存量项目庞大**：大量企业级项目基于 Vue 2 构建，短期内无法迁移
- **组件库生态**：Element UI、Ant Design Vue 1.x、iView 等成熟组件库仍在广泛使用
- **Vue 2.7 延续**：Vue 官方发布 2.7 版本，将 Composition API 回移，延长了 Vue 2 的生命周期
- **迁移成本高**：Vue 2 → Vue 3 的迁移涉及大量 Breaking Changes，需要渐进式过渡

## 2. Vue 2 组件库文档化的痛点

### 2.1 现有方案的局限性

| 方案                    | 问题                                 |
| ----------------------- | ------------------------------------ |
| **VuePress 1.x**        | 仅支持静态文档，无法实时编辑预览组件 |
| **Storybook for Vue 2** | 配置复杂，与中文生态集成较差         |
| **手工编写文档**        | 维护成本高，API 与代码容易不同步     |
| **自建文档系统**        | 开发成本高，功能不完善               |

### 2.2 理想的组件文档方案应具备

1. **Live Editing** - 在浏览器中实时编辑和预览组件
2. **API 自动提取** - 从源码自动生成 Props、Events、Slots 文档
3. **TypeScript 支持** - 正确解析和展示类型信息
4. **样式预处理** - 支持 LESS、SCSS 等预处理器
5. **HMR 支持** - 开发时热更新，提升效率
6. **中文友好** - 良好的中文文档和社区支持

## 3. dumi 生态的定位

### 3.1 dumi 简介

[dumi](https://d.umijs.org/) 是蚂蚁金服开源的组件/函数库文档工具，具有以下特点：

- **专为组件库设计** - 不仅是文档站点，更是组件开发工具
- **Live Demo 支持** - 代码块即组件，可实时编辑预览
- **API 自动生成** - 基于 TypeScript 类型自动生成 API 文档
- **主题丰富** - 支持自定义主题，社区有丰富的主题选择
- **Umi 生态** - 与 Umi、Ant Design 生态深度集成

### 3.2 dumi 的多框架支持

dumi 采用 **preset** 机制支持不同技术栈：

```
dumi
├── 内置 React 支持
├── @dumijs/preset-vue (Vue 3)
└── @dumijs/preset-vue2 (Vue 2) ← 本项目
```

### 3.3 为什么选择扩展 dumi

| 对比维度   | 扩展 dumi              | 自建方案     |
| ---------- | ---------------------- | ------------ |
| 开发成本   | 低，复用 dumi 基础设施 | 高，从零开始 |
| 功能完整性 | 高，继承 dumi 全部能力 | 取决于投入   |
| 社区支持   | 好，dumi 有活跃社区    | 无           |
| 维护成本   | 低，随 dumi 升级       | 高，完全自主 |
| 主题生态   | 可复用 dumi 主题       | 需自行开发   |

## 4. preset-vue2 的目标

### 4.1 核心目标

**让 Vue 2 组件库能够使用 dumi 进行文档化，获得与 React/Vue 3 同等的开发体验。**

### 4.2 具体目标

1. **无缝集成** - 作为 dumi preset，一行配置即可启用
2. **功能对齐** - 与 preset-vue (Vue 3) 保持功能对等
3. **开发体验** - Live Editing + HMR + API 自动提取
4. **生产可用** - 经过实际项目验证，稳定可靠
5. **易于维护** - 代码结构清晰，便于后续扩展

### 4.3 非目标

- 不支持 Vue 2.5 及更早版本（主要面向 2.6/2.7）
- 不支持 Class Component（vue-class-component）的 API 提取
- 不替代 Vue 3，而是作为过渡方案

## 5. 项目价值

### 5.1 对企业的价值

- **降低迁移成本**：无需重写文档系统，直接使用 dumi
- **提升开发效率**：Live Editing 加速组件开发迭代
- **规范化文档**：自动 API 提取确保文档与代码同步

### 5.2 对社区的价值

- **填补空白**：dumi 生态首个 Vue 2 preset
- **最佳实践**：为其他框架 preset 提供参考
- **促进迁移**：帮助 Vue 2 项目渐进式迁移到现代化文档方案

### 5.3 技术价值

- **深入理解 dumi**：preset、tech stack、atom parser 机制
- **Vue 2 编译原理**：SFC 编译、JSX 转换、scoped styles
- **浏览器端编译**：Babel Standalone、运行时编译策略

## 6. 总结

preset-vue2 的诞生源于一个简单的需求：**让 Vue 2 组件库也能享受 dumi 带来的现代化文档开发体验**。

通过扩展 dumi 而非重新造轮子，我们能够：

- 最大化复用现有基础设施
- 与 dumi 生态保持同步
- 专注于 Vue 2 特有的技术挑战
