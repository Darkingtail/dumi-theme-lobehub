⏺ Good question! The API Table feature has limitations with third-party
  libraries like Element UI:

  Why it won't work directly

  The vue-docgen-api parser needs source code to extract metadata. For
  Element UI:

  - Components are pre-compiled in node_modules
  - No .vue source files to parse
  - Can't extract JSDoc comments from bundled code

  What you can do

  Option 1: Manual API docs (recommended)

  Write the API table manually in markdown:

  ## Button Props

  | Prop | Type | Default | Description |
  |------|------|---------|-------------|
  | type | string | 'default' | 按钮类型 |
  | size | string | - | 按钮尺寸 |
  | disabled | boolean | false | 是否禁用 |

  Option 2: Wrapper components

  Create a wrapper that documents Element UI props:

  <script>
  /**
   * Element UI Button wrapper
   * @displayName ElButton
   */
  export default {
    name: 'ElButton',
    props: {
      /** 按钮类型 */
      type: { type: String, default: 'default' },
      /** 按钮尺寸 */
      size: String,
      /** 是否禁用 */
      disabled: { type: Boolean, default: false },
    },
    render(h) {
      return h('el-button', { props: this.$props }, this.$slots.default);
    },
  };
  </script>

  Option 3: Use Element UI's docs

  Link to Element UI's official documentation for props reference.

  ---
  Summary: API Table is best for your own components. For third-party libs,
  manual documentation is the standard approach.

> is preset-vue(vue3 version) support for third-party comp? 

⏺ No, preset-vue (Vue 3) has the same limitation. It also uses
  vue-docgen-api which requires source code.

  Both presets have the same constraint:

  |                  | preset-vue (Vue 3) | preset-vue2 (Vue 2) |
  |------------------|--------------------|---------------------|
  | Own components   | ✅ Supported        | ✅ Supported         |
  | Third-party libs | ❌ No               | ❌ No                |

  Why?

  Both use static analysis that needs:
  - Original .vue / .tsx source files
  - JSDoc comments in source code
  - Uncompiled/unbundled code

  Third-party packages in node_modules are:
  - Pre-compiled to JS
  - Minified (comments stripped)
  - No source .vue files

  Industry standard

  This is the same for all documentation tools:
  - Storybook - can't auto-extract third-party props
  - VuePress - manual docs for external libs
  - Docusaurus - same limitation

  The solution is always: manual documentation or wrapper components for
  third-party libraries.
