# 基于源码对比分析，总结如下：

preset-vue2 vs preset-vue 功能对比

✅ 已达到功能对等

| 功能                            | 状态 |
| ------------------------------- | ---- |
| SFC 编译 (.vue 文件)            | ✅   |
| JSX/TSX 支持                    | ✅   |
| TypeScript 支持                 | ✅   |
| CSS/SCSS/LESS 预处理            | ✅   |
| Props/Events/Slots/Methods 提取 | ✅   |
| Webpack 集成                    | ✅   |
| 热更新 (HMR)                    | ✅   |
| 实时编辑 (Live Editing)         | ✅   |
| 错误提示                        | ✅   |

⚠️ preset-vue (Vue 3) 有但 preset-vue2 缺失的功能

| 功能                     | 说明                                     | 影响程度 |
| ------------------------ | ---------------------------------------- | -------- |
| TypeScript 类型服务      | Vue 3 使用 @dumijs/vue-meta + TypeScript |
| 语言服务，可完整解析类型 | 中                                       |
| CodeSandbox 代码生成     | getPreviewerData.ts 生成完整导出代码     | 低       |
|                          |
| Computed 属性提取        | TypeScript 分析可自动提取                | 低       |
|                          |
| 生命周期钩子文档         | TypeScript 推断                          | 低       |
|                          |

🚀 preset-vue2 独有优势

| 功能               | 说明                                         |
| ------------------ | -------------------------------------------- |
| React/Vue 代码区分 | looksLikeReactCode() 防止 React 代码被误处理 |
| JSX 路径过滤       | jsxIncludes 精细控制哪些 JSX 文件被处理      |
| 浏览器端 LESS/SCSS | 无需构建即可在线编译                         |
| LRU 编译缓存       | 浏览器端智能缓存                             |
| 双语错误提示       | 中英文错误信息                               |
| Vue.extend() 兼容  | 实时编辑时自动处理                           |
| 枚举值提取增强     | 从 validator 函数提取枚举值                  |

📊 结论

preset-vue2 在核心功能上已与 preset-vue 对等，主要差距在于：

1. TypeScript 类型分析深度 - Vue 3 版本使用完整的 TypeScript
   语言服务，可以解析更复杂的类型推断。Vue 2 版本依赖 vue-docgen-api 字符串解析。
2. 对于实际使用影响不大 - 因为 Vue 2 组件通常使用 Options
   API，类型定义相对简单，vue-docgen-api 已能满足大部分需求。

建议：当前功能已足够生产使用，TypeScript 类型服务升级可作为远期优化目标，但 ROI 不高。
